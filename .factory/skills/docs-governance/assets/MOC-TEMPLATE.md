# 开发文档 MOC（docs/ 索引）

> 本文件是 docs/ 目录的**索引文档（MOC, Map of Content）**：docs/ 下增删、移动文档后必须同步更新本文件（分区索引 + 文档谱系表）。项目入口见 [根目录 README](../README.md)。

## 命名与流转规范

docs/ 文档分两类：

- **流转文档**（backlog/ → specs/ → frozen/）：目录即状态，同一文件 `git mv` 前进；每个主题同一时刻最多一份活跃（位于 backlog/ 或 specs/）。
- **常驻文档**（analysis/、reference/）：原地维护、版本号递增，不进入 specs/；提案以链接引用它们作为起源。只服务单一规格的分析在该规格冻结时随之冻结。

| 状态 | 位置 | 命名 | 编号 |
|------|------|------|------|
| 候选提案 / 遗留台账 | backlog/ | `<kebab-case>_backlog.md` | 无 |
| 开发中规格 | specs/ | `<NAME>_SPEC.md`（SCREAMING） | 无 |
| 已冻结规格 / 台账 | frozen/ | `<NN>_<NAME>_frozen.md` | 有 |
| 谱系存档（提案 / 绑定型分析） | frozen/ | `<原名>_backlog_frozen.md` / `<原名>_frozen.md` | 无 |

编号三纪律：编号 = 冻结顺序（近似实现顺序），冻结时取 frozen/ 现有最大编号 +1，永不复用、不插入（重开后再冻结沿用原编号）；非系列台账同样参与编号；frozen/ 中不带编号的文件都是谱系存档。流转事件后运行文档链接/索引 drift guard 测试确认零坏链、索引无遗漏。

流转方式词表（谱系表使用）：单文件晋升 / 提案存档 / 拆分移交 / 跳过提案 / 重开 / 派生台账 / 止于分析。定义见 docs-governance skill §2.1。

## 文档谱系

一个主题一行，记录文档间的对应关系与流转方式；状态描述见下方分区索引。每次立项、冻结、拆分、重开、派生台账都更新对应行。

| 主题 / 系列 | 起源 | 提案 | 规格 | 后续 | 流转方式 |
|-------------|------|------|------|------|----------|
| 示例主题（X） | [示例分析.md](analysis/示例分析.md) §2 | — | [01_示例规格_frozen.md](frozen/01_示例规格_frozen.md) | [示例提案.md](backlog/示例提案.md)（遗留台账） | 单文件晋升 → 派生台账 |

## specs/ — 开发规格（落点）

**立项后新规格的存放处**（从 [backlog/](backlog/) 晋升）。当前为空。

新规格格式对齐 frozen/ 中的规格先例：含模块设计、测试方案、任务排期与进度跟踪表，任务编号用新前缀避免冲突。

## frozen/ — 已冻结文档

任务全部收口、不再新增或改动任务的规格与台账，以及谱系存档，作为架构与设计参考保留。

| 文档 | 说明 |
|------|------|
